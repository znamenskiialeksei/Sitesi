### 0.4. Регламент редактирования, мультиязычного перевода, перемещения и добавления строк на Листе 1

> 🔒 **СТАТУС РАЗДЕЛА:** Неприкосновенная База Старта [Starting Baseline]. Строгий READ-ONLY для всех ИИ-агентов. Регламент разделения зон редактирования, ассоциативной адресации по ключам и формул автоперевода с точкой с запятой является неизменным архитектурным законом.

#### 0.4.1. Порядок редактирования данных
1. **Зона исключительной ответственности суперхозяина:**  
   Владелец виллы редактирует исключительно:
   * **Колонку D [RU]:** Тексты на русском языке;
   * **Колонку G [Медиа / Иконка / Ссылка]:** Ссылки на медиафайлы Google Drive, CDN Unsplash, имена иконок Lucide или параметры разделителей `|`;
   * **Колонку H [Статус]:** Переключатель `Вкл` или `Выкл`.
2. **Запрет ручной правки колонок E и F:**  
   Категорически запрещено вручную вносить статический текст в ячейки колонок E [`EN`] и F [`TR`]. Любая ручная запись в эти ячейки затирает формулу динамического массива `MAP(LAMBDA)` и останавливает автоперевод всех последующих строк листа.

#### 0.4.2. Порядок мультиязычного автоперевода [Стандарт формул с точкой с запятой `;`]
1. В ячейках **E2** и **F2** закреплены формулы динамических массивов Google Таблиц, транслирующие текст из колонки D во все последующие строки листа:

#### 0.12.6. Механизм Умного Выбора Ступени Отката и Протокол Мгновенного Восстановления [Smart Rollback Selector Protocol]
Для обеспечения гибкости и удобства суперхозяина восстановление из отката оснащено **интеллектуальным интерактивным селектором** с тремя режимами работы:

   `[Enter : Восстановить последнюю ступень СТУПЕНЬ_02_Новая_Веха_260920261600]`.  
   Нажатие одной клавиши `Enter` немедленно запускает процедуру возврата.

2. **Режим 2 : Умный интерактивный выбор любой ступени из реестра [Interactive Smart Picker]:**  
   Сценарий выводит на экран наглядный нумерованный реестр всех доступных ступеней с датами, названиями вех и кратким описанием из паспорта:  
   ```
   === РЕЕСТР ДОСТУПНЫХ СТУПЕНЕЙ ОТКАТА [villa-turaman-airbnb-platform] ===
   [1] СТУПЕНЬ_01_Базовый_эталон_старта_260920261545 : Базовый эталон, 14 листов CRM, меню, автоформатирование
   [2] СТУПЕНЬ_02_Интеграция_Платежей_260920261700  : Подключение нового шлюза, тесты пройдены
   ----------------------------------------------------------------------
   Введите номер ступени [1-2] или нажмите Enter для выбора последней [2]:
   ```
   Пользователь вводит цифру [1, 2, ...] : скрипт сам автоматически вычисляет, подставляет полный физический путь к папке ступени и выполняет верификацию целостности.

3. **Режим 3 : Прямая передача ступени через параметры или путь [Direct Parameter / Path Injection]:**  
   Скрипт принимает как порядковый номер, так и прямой относительный или абсолютный путь к любой архивной папке:  
   ```powershell
   # Откат по номеру ступени
   pwsh -ExecutionPolicy Bypass -File .\restore_rollback_stage.ps1 -ProjectName "villa-turaman-airbnb-platform" -StageNumber 1

   # Откат с умным интерактивным диалогом [по умолчанию последняя]
   pwsh -ExecutionPolicy Bypass -File .\restore_rollback_stage.ps1 -ProjectName "villa-turaman-airbnb-platform"

   # Откат по точному имени папки или пути
   pwsh -ExecutionPolicy Bypass -File .\restore_rollback_stage.ps1 -ProjectName "villa-turaman-airbnb-platform" -StagePath "Эталонный код для отката\villa-turaman-airbnb-platform\СТУПЕНЬ_01_Базовый_эталон_старта_260920261545"
   ```

**Защитный алгоритм выполнения отката [Safe Execution Pipeline]:**
* **Шаг 1 [Создание Stash]:** Текущее рабочее состояние проекта перед перезаписью автоматически архивируется во временную защитную папку `_ROLLBACK_STASH_[ДатаВремя]`, исключая потерю незафиксированных правок;

### 1.11. Мандат динамических диапазонов Google Sheets API: Anti-Hardcoded Range Mandate
* **Категорический запрет хардкода диапазонов:** Запрещено жестко прописывать буквенные границы колонок [например, `'A2:G'`, `'A2:K'`, `'A1:M500'`] при записи массивов данных в Google Таблицы.
* **Динамический расчет границ:** Границы диапазона A1 Notation обязаны вычисляться исключительно динамически на основе фактической максимальной ширины строк массива [`Math.max(...matrix.map(r => r.length))`] либо через универсальную функцию-генератор `getBoundingRange(sheetTitle, startCol, startRow, matrix)` и `colIndexToLetter`.
* **Цель:** Полное исключение системных ошибок Google Sheets API `Requested writing within range [A2:G], but tried writing to column [H]`, гарантируя 100% устойчивость скриптов при любом расширении структуры листов.

<a name="112-мандат-паритета-двух-каналов-самоисцеления-dual-channel-parity-mandate"></a>
### 1.12. Мандат паритета двух каналов самоисцеления: Dual-Channel Parity Mandate
* **Два равнозначных контура:** В экосистеме платформы действуют два параллельных контура восстановления и самоисцеления базы данных:
  1. *Браузерный контур:* Google Apps Script [`google-apps-script/Code.js`] : интерактивные меню и триггеры таблицы [`restoreSheetsFromCloudApiInteractive`, `restoreFromDriveSnapshotFileId_`, `initSingleSheetByKey_`];
  2. *Серверный контур:* Node.js CLI [`scripts/restore-sheets.js`] : автоматический запуск через задачу `npm run restore-sheets` [Задача `6` в `.vscode/tasks.json`].

* **Цель:** Искоренение скрытых регрессий [«спящих ошибок»], когда листы успешно создаются из одного места, но падают при вызове из другого.

### 1.14. Мандат безопасного доступа к свойствам конфигураторов: Defensive Config Property Mandate
* **Запрет слепого доступа:** Категорический запрет на прямое обращение к вложенным свойствам конфигурационных объектов [`cfg.headers.length`, `cfg.minWidths[c]`] без предварительной проверки на существование [`null-checking`] и безопасного дефолтного значения [`fallback`].
* **Обязательный стандарт:**
  ```javascript
  var headers = (cfg && Array.isArray(cfg.headers) && cfg.headers.length > 0) ? cfg.headers : null;
  var maxCols = headers ? headers.length : (dataRows && dataRows[0] ? dataRows[0].length : 1);
  ```
* **Цель:** Исключение фатальных сбоев `TypeError: Cannot read properties of undefined (reading 'length')` в Google Apps Script и Node.js.

<a name="115-мандат-безопасных-правил-проверки-данных-и-чистоты-коридора-формул-массива-safe-data-validation--array-formula-spill-mandate"></a>
### 1.15. Мандат безопасных правил проверки данных и чистоты коридора формул массива: Safe Data Validation & Array Formula Spill Mandate
* **Предварительная очистка валидаций перед пакетной записью:** В Google Apps Script метод `clearDataValidations()` существует на объекте `Range`, а на объекте `Sheet` применяется `sheet.clear({ contentsOnly: true, validationsOnly: true })` либо `sheet.getRange(1, 1, maxR, maxC).clearDataValidations()`. При любых процедурах восстановления, импорта или перезаписи листов из эталонов и снимков обязательно очищать правила проверки данных перед `range.setValues()`.
* **Защитный режим валидации без исключений [`setAllowInvalid: true`]:** Все правила валидации в скриптах Google Apps Script обязаны создаваться с параметром `.setAllowInvalid(true)`. Это сохраняет выпадающие списки для интерактивной работы человека в таблице, но полностью исключает аварийные сбои скрипта при программной пакетной записи значений.
* **Универсальные правила для колонок доступности и наличия:** Колонки со статусом «Наличие» [`SERVICES`: колонка 13 / `M`, `GUIDES`: колонка 19 / `S`] обязаны принимать оба эквивалентных стандарта: `['Да', 'Нет', 'Вкл', 'Выкл']`.
* **Очистка коридора развертывания формул массива [Spill Corridor Clearance]:** Формулы массива [`MAP/LAMBDA`, `ARRAYFORMULA`] требуют полностью свободных ячеек ниже строки 2 по всей длине колонки. Запрещено записывать статический текст в ячейки колонок, управляемых формулами массива. Перед вызовом `range.setValues(rectRows)` и после вставки формул в строку 2 значения во всех формульных колонках ниже строки 2 обязаны быть очищены [`clearContent()`], гарантируя мгновенное развертывание формул без ошибок блокировки `#REF!`.
* **Нормализация регистра эталонов:** Все бинарные флаги в эталонных массивах [`masterSeedContent.js`, `Code.js`, `restore-sheets.js`] обязаны соблюдать единый регистр Title Case: `Да`, `Нет`, `Вкл`, `Выкл`.

<a name="27-тотальный-стандарт-искоренения-скобок-и-длинного-тире-total-zero-brackets--zero-emdash-policy"></a>
### 2.7. Тотальный стандарт искоренения скобок и длинного тире: Total Zero-Brackets & Zero-Emdash Policy
* **Глубинная первопричина:** Символ длинного тире `—` [U+2014] в кодировке UTF-8 состоит из трех байт: `0xE2 0x80 0x94`. Байт `0x94` в системной русской кодовой странице Windows [Windows-1251] является символом закрывающей типографской кавычки `”`. При разборе строк парсер PowerShell воспринимает байт `0x94` как кавычку и досрочно закрывает строковый литерал прямо посреди текста, разрушая синтаксическое дерево. Круглые скобки `()` вызывают аналогичный сбой токенизатора `MissingEndParenthesisInExpression`.
* **Императивный абсолютный запрет:** В проекте категорически запрещено использовать типографское длинное тире `—` [U+2014] и любые круглые скобки `()` внутри:
  1. Любых строковых литералов, сообщений `Write-Host`, `echo` и логов PowerShell/Bash;
  2. Любых комментариев на русском языке в `.ps1`, `.sh`, `.json`, `.js`, `.md`;
  3. Названий задач в `.vscode/tasks.json` [поле `"label"`];
  4. Названий создаваемых папок, файлов, скриптов, сценариев и артефактов;
  5. Любых текстов и заголовков, генерируемых агентом.
* **Единый канонический разделитель:** Везде вместо скобок и длинного тире используется строго стандартный однобайтовый **ASCII-дефис `-` [код `0x2D`]**, двоеточие `:` или квадратные скобки `[]`. Байт `0x2D` во ВСЕХ кодировках мира означает исключительно знак минус/дефис и физически исключает синтаксическую коллизию.
* **Обязанность агента по авто-санитизации:**
  1. При создании любых названий агент обязан автоматически исключать скобки и длинные тире, заменяя их на стандартный дефис `-` или квадратные скобки `[]`.
  2. Если пользователь сам создал или передал название со скобками или длинным тире, агент ОБЯЗАН АВТОМАТИЧЕСКИ нормализовать его в кодовой базе и скриптах, навсегда исключая сбои парсера.
  3. Исторические системные пути со скобками [папка Накопителя и Запускатора переноса] определяются в сценариях строго динамически через прямое сопоставление по маске [`$d.Name -like "*перенос*"` или `$d.Name -like "*накопитель*"`].

<a name="28-изоляция-рабочей-папки-options-cwd-в-vscodetasksjson"></a>
### 2.8. Изоляция рабочей папки options cwd в .vscode/tasks.json
* **Механика сбоя:** При запуске задачи VS Code вызывает команду через аргумент `pwsh.exe -Command <команда>`. При этом системный вызов Windows `CommandLineToArgvW` автоматически сбрасывает внешние кавычки, оставляя путь со скобками незащищенным. В результате PowerShell воспринимает скобки как оператор вызова выражения и падает с ошибкой.
* **Канонический стандарт изоляции:** Все задачи в `.vscode/tasks.json`, запускающие скрипты из папок проекта или Накопителя, ОБЯЗАНЫ указывать путь к каталогу в опции `"options": { "cwd": "${workspaceFolder}/..." }`, а в поле `"command"` передавать строго чистое относительное имя:
  ```json
  "label": "🔄 22. Применение Настроек Накопителя : apply_settings.ps1 -> Все проекты и задачи -> Каскадное распространение глобальных настроек",
  "type": "shell",
  "command": "pwsh -ExecutionPolicy Bypass -File .\\apply_settings.ps1",
  "options": {
    "cwd": "${workspaceFolder}/Глобальные настройки проекта (накопитель)"
  }
  ```
  Это гарантирует, что в самой строке команды скобок нет вообще, и синтаксический сбой парсера исключен на 100%.

<a name="29-детерминированные-циклы-foreach-в-сценариях-powershell"></a>
### 2.9. Детерминированные циклы foreach в сценариях PowerShell
* **Запрет многострочных конвейеров Where-Object:** Во всех сценариях `.ps1` категорически запрещено использовать многострочные конвейерные блоки `Where-Object { ... }` с кириллическими условиями и операторами `-or`, так как в среде Windows они могут вызывать сбой токенизатора `UnexpectedToken: "}"`.
* **Императивный стандарт:** Любая фильтрация и обход файлов, папок и коллекций реализуются СТРОГО через прямые детерминированные циклы:
  ```powershell
  foreach ($item in $items) {
      $n = $item.Name
      if ($n -eq "имя1" -or $n -eq "имя2") { ... }
  }
  ```

* **Управление режимом обслуживания:**
  - **Пауза сайта [сценарий `pause_site.ps1` / Задача 16 в `.vscode/tasks.json` / pwsh]:** Автоматически генерирует фирменную страницу-заглушку `maintenance.html`, формирует конфигурацию маршрутизации `vercel.json` с кодом ответа `503 Service Unavailable` и отправляет коммит в origin. Код HTTP 503 указывает поисковым роботам [Яндекс, Google], что сайт временно недоступен по техническим причинам, сохраняя все позиции в поисковой выдаче без исключения страниц из индекса.
  - **Возобновление работы [сценарий `resume_site.ps1` / Задача 17 в `.vscode/tasks.json` / pwsh]:** Удаляет заглушку и файл перенаправления, фиксирует коммит и пушит в origin, инициируя автоматическую пересборку Next.js платформы на Vercel.
  - **Полная ликвидация вызовов внешнего bash:** Задачи VS Code вызывают сценарии строго через нативный `pwsh -ExecutionPolicy Bypass -File .\pause_site.ps1` без промежуточных консолей и внешних утилит.
