# План: Ликвидация сбоя обновления сайта и прямая доставка Duplex SSOT

## 1. Контекст и первопричина проблемы
В течение 24 часов изменения из Google Таблицы не отображались на сайте www.villaturaman.com из-за 3 системных ловушек в архитектуре:
1. Ошибка подписи сервисного аккаунта Google Cloud: GOOGLE_PRIVATE_KEY на Vercel выдавал invalid_grant: Invalid JWT Signature. При ошибке сервер стирал свежий кэш и принудительно возвращал устаревший локальный content.json.
2. Самоуничтожение кэша со стороны браузера: в pages/index.js клиентский код вызывал fetch('/api/content?force=true'). При каждом открытии страницы браузер форсировал обращение к Google API, ловил ошибку JWT и сбрасывал кэш на старый файл.
3. Рассинхронизация адресов доставки: вебхук из Google Таблицы отправлялся на технический адрес ветки Vercel preview вместо боевого канонического домена https://www.villaturaman.com, а изолированная память Vercel не передавала данные между разными инстансами. Также в коде присутствовали остаточные ссылки на localhost.

## 2. Реализованные системные исправления
1. utils/liveContentSync.js:
   - Внедрена функция updateLiveContentFromPayload для прямого приема данных всех листов из Google Apps Script.
   - Установлена защита: при ошибке JWT подписи Google API сервер проверяет наличие данных, переданных из Google Apps Script, и отдает их вместо устаревшего дискового файла content.json.
2. pages/index.js:
   - Удален разрушительный параметр force=true из клиентского запроса. Клиент запрашивает актуальный кэш без сброса памяти.
3. pages/api/revalidate.js и pages/api/content.js:
   - Добавлен прием livePayload и немедленное обновление кэша в оперативной памяти сайта.
4. google-apps-script/Code.js:
   - В функции collectAllSheetsPayload_ реализован сбор данных всех 14 листов таблицы.
   - В triggerRevalidateWebhook организована одновременная доставка на www.villaturaman.com и резервный адрес Vercel.
   - Обеспечен информативный тост в Google Таблице с подтверждением доставки.
5. Искоренение localhost:
   - Проведена тотальная очистка всех скриптов и файлов от localhost:3000.
6. Синхронизация между вариантами:
   - Изменения Code.js и вспомогательных модулей синхронизированы в variant2-classic и platform.

## 3. Порядок применения пользователем
1. Отправка ветки v1-airbnb в GitHub: задача VS Code 16 или скрипт push_project_to_github.ps1 с параметром Target v1.
2. Копирование обновленного файла Code.js в редактор Apps Script в Google Таблице и сохранение Ctrl+S.
3. Нажатие кнопки меню 1. Опубликовать изменения на сайте прямо сейчас.
