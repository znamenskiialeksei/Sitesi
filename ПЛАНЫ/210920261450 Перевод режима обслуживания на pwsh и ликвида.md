## 1. Выявление первопричин сбоев [Root Cause Analysis]

### Первопричина 1: Сбой выполнения задач перевода в режим обслуживания и обратно в VS Code
* **Где возникает**: В задачах `.vscode/tasks.json`:
  - `⏸️ [Вариант 1 - Airbnb] Перевести сайт в режим обслуживания - Vercel Pause`
  - `▶️ [Вариант 1 - Airbnb] Возобновить штатную работу сайта - Vercel Resume`
  - [а также аналогичные задачи для Варианта 2 Classic и Варианта 3 Base].
* **Механика сбоя**:
  1. В `.vscode/tasks.json` все эти задачи вызывали:
     `command: bash ".\160519092026 Исторические скрипты запуска корня\pause-site.sh"`
     `command: bash ".\160519092026 Исторические скрипты запуска корня\resume-site.sh"`.
  2. Пользователь работает в Windows, где штатной оболочкой терминала VS Code является **PowerShell 7 [pwsh.exe]**. В PowerShell команда `bash` не является встроенной. Если утилита `bash.exe` отсутствует в системной переменной `PATH`, терминал выбрасывает ошибку:
     `bash : Имя "bash" не распознано как имя командлета, функции, файла сценария...`
  3. Даже при наличии Git Bash передача путей с обратными слэшами `.\` и пробелами в кириллических названиях архивов [`160519092026 Исторические скрипты запуска корня`] приводит к синтаксическим сбоям внутри `bash`.
  4. Скрипты находились в архивной папке, что нарушает **Правило 2.8** [запрет использования архивных каталогов для активных задач VS Code] и **Правило 2.3** [стандарт PowerShell 7 pwsh.exe].
  5. В меню `deploy_and_run.ps1` проектов пункты перевода в режим обслуживания также пытались вызывать `bash`.

---

### Первопричина 2: Появление папки-дубля `Глольные настройки проекта (запускатор перенос)`
* **Где возникает**: В каталоге `Глобальные настройки проекта (накопитель)/`.
* **Механика сбоя**:
  1. На ранних этапах работы при запуске сценария пересборки в окружении без явной сигнатуры UTF-8 BOM или под Windows PowerShell 5.1 русская буква «б» или «ба» в имени `Глобальные...` была искажена в байты замены Unicode `0xFFFD` [символ заменяющего знака], создав каталог `Глольные настройки проекта (запускатор перенос)`.
  2. В сценарии `rebuild_portable_launcher.ps1` использовался не детерминированный путь, а поиск по маске:
     `foreach ($d in $allDirs) { if ($d.Name -like "*перенос*") { $PortableDir = $d.FullName; break } }`.
     В результате поврежденная папка могла определяться как целевая.
  3. Далее в цикле копирования `foreach ($item in $items) { if ($in -like "*перенос*") continue ... }` при несовпадении кодовых страниц имя правильной папки `Глобальные настройки проекта (запускатор перенос)` не отфильтровывалось и копировалось внутрь поврежденной папки.
  4. Сценарий `clean_accumulator_and_root.ps1` не содержал блока проверки имен на наличие поврежденных символов и удалял только строго заданные шаблоны.

## 2. Реализованные системные изменения [Total Root Cause Elimination]

### Блок 1: Создание нативных PowerShell 7 сценариев режима обслуживания
* **Созданы новые файлы со 100% стандартом UTF-8 BOM, snake_case и Zero-Brackets**:
  1. `villa-turaman-airbnb-platform/pause_site.ps1` и `resume_site.ps1` [Целевая ветка: `v1-airbnb`]
  2. `villa-turaman-variant2-classic/pause_site.ps1` и `resume_site.ps1` [Целевая ветка: `v2-classic`]
  3. `villa-turaman-platform/pause_site.ps1` и `resume_site.ps1` [Целевая ветка: `v3-initial`]
  4. `Глобальные настройки проекта (накопитель)/manage_maintenance.ps1` [Централизованный диспетчер с параметрами `-Action pause|resume` и `-Target v1|v2|v3`].
  5. Синхронизировано в `Глобальные настройки проекта (запускатор)/manage_maintenance.ps1`.
* **Функционал `pause_site.ps1`**:
  - Генерирует фирменную адаптивную страницу-заглушку `maintenance.html` [код HTTP 503 Service Unavailable, градиенты, карточка, реквизиты VKN 9991120181, текст на русском и английском];
  - Формирует `vercel.json` с правилом перенаправления всех запросов `/(.*)` на `/maintenance.html` со статусом 503 для 100% сохранения поисковой индексации SEO;
  - Проверяет наличие Git: если репозиторий активен, выполняет `git add -f maintenance.html vercel.json`, коммит и отправку в целевую ветку платформы для авто-деплоя на Vercel.
* **Функционал `resume_site.ps1`**:
  - Удаляет `maintenance.html` и `vercel.json`;
  - Фиксирует удаление в Git и отправляет коммит в ветку, инициируя пересборку боевого сайта на Vercel;
  - Выводит понятный цветной статус о возвращении платформы в строй.
