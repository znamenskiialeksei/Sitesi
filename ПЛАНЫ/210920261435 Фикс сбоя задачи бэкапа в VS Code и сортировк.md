## 1. Выявленные первопричины сбоев [Root Cause Analysis]

### Первопричина 1: Сбой выполнения задачи бэкапа в VS Code
* **Где возникает**: При запуске задачи `"💾 SPARK: Универсальное создание двухуровневого бэкапа и сохранение версии"` в `.vscode/tasks.json`.
* **Механика сбоя**:
  1. В задаче настроена изоляция рабочей папки: `"cwd": "${workspaceFolder}/Глобальные настройки проекта (накопитель)"`.
  2. В сценарии `create_project_backup.ps1` на строке 31 поиск корня рабочей области производился циклом:
     `while ($WorkspaceRoot -and -not (Test-Path -LiteralPath (Join-Path $WorkspaceRoot "GEMINI.md")))`.
  3. Поскольку файл `GEMINI.md` находится прямо внутри `Глобальные настройки проекта (накопитель)` [являясь Единственным Законодательным Сводом Накопителя], условие цикла сразу возвращало `$false`.
  4. Скрипт ошибочно считал, что папка Накопителя и есть корень репозитория, после чего искал проект `villa-turaman-airbnb-platform` внутри `Глобальные настройки проекта (накопитель)\villa-turaman-airbnb-platform`.
  5. Скрипт выбрасывал ошибку `[ОШИБКА] Проектная папка не найдена` и аварийно завершался с кодом 1.

### Первопричина 2: Отсутствие сортировки версий по подпапкам проектов
* **Где возникает**: В папке `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/`.
* **Проблема**: Все версии различных вариантов платформы [Airbnb `villa-turaman-airbnb-platform`, Классический `villa-turaman-variant2-classic`, Базовый `villa-turaman-platform`] сохранялись сплошным неструктурированным списком в корень `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/`, создавая путаницу между разными вариантами проекта.
* **Требование пользователя**: Зафиксировать стандарт, что сохранение версий в `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/` обязано происходить со строгой сортировкой в подпапки с именами соответствующих проектов по общей форме именования.

## 2. Реализованные изменения

### Блок 1: Системное исправление поиска корня в `create_project_backup.ps1`
* **Файлы**:
  - `Глобальные настройки проекта (накопитель)/create_project_backup.ps1`
  - `Глобальные настройки проекта (запускатор)/create_project_backup.ps1`
* **Изменения**:
  - Заменен уязвимый поиск по `GEMINI.md` на детерминированный поиск корня монорепозитория по уникальной комбинации корневых маркеров:
    `Test-Path (Join-Path $WorkspaceRoot "СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА")` И `Test-Path (Join-Path $WorkspaceRoot "Глобальные настройки проекта (накопитель)")` И `Test-Path (Join-Path $WorkspaceRoot $ProjectName)`.
  - При таком условии скрипт гарантированно поднимается из папки Накопителя в истинный корень репозитория.

---

### Блок 2: Реализация сортировки версий по подпапкам проектов в `create_project_backup.ps1`
* **Архитектурный стандарт**:
  - Для каждого проекта в `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/` создается изолированная подпапка с каноническим системным именем проекта:
    * `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/villa-turaman-airbnb-platform/`
    * `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/villa-turaman-variant2-classic/`
    * `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/villa-turaman-platform/`
  - Версии конкретного проекта сохраняются строго внутри его персональной подпапки:
    `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/$ProjectName/$Timestamp Версия $VersionNumber $ReleaseTitle/`
  - Номер версии `$VersionNumber` вычисляется изолированно внутри подпапки целевого проекта, не смешивая нумерацию с другими ветками и вариантами.
  - Внедрен блок автоматической бесшовной миграции существующих версий из корня `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/` в подпапки проектов.
