# ПЛАН: Восстановление прямой регистрации AuthModal с двухфакторной OTP-верификацией

**Дата создания:** 28.09.2026 10:10  
**Статус:** 100% ВЫПОЛНЕНО И ВЕРИФИЦИРОВАНО  
**Область действия:** `components/Modals/AuthModal.js`, `components/Modals/VerificationModal.js`, `context/AuthContext.js`, `pages/api/booking.js`, `АРХИТЕКТУРА УЧЕТА ГОСТЕЙ`  

---

## 1. Первопричины дефекта [Total Root Cause Elimination]

1. **Конфликт z-index модальных окон:**
   Модальное окно `VerificationModal` обладало z-index `z-[100]`, в то время как родительское модальное окно `AuthModal` находилось на `z-[1000]`. При открытии формы верификации из `AuthModal` окно подтверждения кода визуально перекрывалось темным фоном `bg-black/80` окна авторизации и становилось невидимым и недоступным для взаимодействия.
2. **Ограниченность контекста AuthContext.js:**
   Метод `register` принимал только `name, contact, password` без передачи объекта с раздельными email и телефоном.
3. **Рассогласование серверного кэша при составном контакте:**
   При регистрации клиент передавал составной контакт вида `+79991234567 | guest@domain.com`. Серверный обработчик `action === 'register'` проверял в кэше ключ `verified_email_${safeContact}`, то есть искал ключ `verified_email_+79991234567 | guest@domain.com`, которого не существовало [код сохранялся под `verified_email_guest@domain.com`].
