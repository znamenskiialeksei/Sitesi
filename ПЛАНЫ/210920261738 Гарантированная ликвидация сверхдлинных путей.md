## 1. Описание проблемы и первопричин

1. **Симптом ошибки в VS Code**:
   ```text
   Failed to Commit
   Git add failed: fork/exec C:\Program Files\Git\cmd\git.exe: The filename or extension is too long., output: [error ID: e6be58651ff24926b5e636050dcd4620]
   ```

2. **Глубинные первопричины сбоя**:
   - **Первопричина 1 [Сверхдлинные пути 373 символа на диске]**:
     Внутри каталога `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА\villa-turaman-airbnb-platform\142521092026 Версия 21...\УТВЕРЖДЕННЫЕ_ПЛАНЫ_ИЗМЕНЕНИЙ_ПРОЕКТА\` физически находились 48 файлов планов с длинными русскими названиями. Длина полных путей к этим файлам достигала **373 символов**, что существенно превышало лимит Windows `MAX_PATH` [260 символов].
   - **Первопричина 2 [Почему стандартный Remove-Item не удалил папку]**:
     Стандартные командлеты Windows PowerShell без специального Win32-префикса `\\?\` не могут адресовать пути длиннее 260 символов. Команда удаления завершалась системной ошибкой Windows `ERROR_FILENAME_EXCED_RANGE` [код 206] и каталог оставался на диске.
   - **Первопричина 3 [Механизм сбоя в GUI VS Code]**:
     Когда пользователь нажимает кнопку **Commit** в панели Source Control VS Code без предварительного ручного добавления файлов в индекс [Staged Changes], расширение Git в VS Code пытается выполнить:
     `git add -A -- <путь1> <путь2> ...`
     При попытке передать путь длиной 373 символа, системный вызов Windows `CreateProcessW` завершается сбоем `The filename or extension is too long.` еще до запуска самого Git.

## 2. Реализованные системные решения

### 1. Доработка скрипта санитаризации sanitize_git_tree.ps1
- В сценарий внедрена специализированная функция `Remove-LongPathItem`:
  * Преобразует путь в расширенный формат Win32 `\\?\` [поддержка путей до 32 767 символов];
  * Выполняет удаление через `[System.IO.Directory]::Delete($win32Path, $true)` с запасным вызовом `cmd.exe /c rd /s /q "$win32Path"`;
  * Гарантированно уничтожает каталоги любой глубины вложенности.
- Внедрен вызов `git rm -r --cached --ignore-unmatch` для очистки индекса Git от отслеживания удаленных сверхдлинных путей.
- Внедрен ШАГ 5: автоматический вызов `git add -A` в конце санитизации. Все файлы переводятся в состояние `Staged Changes`, благодаря чему кнопка Commit в VS Code выполняет атомарный `git commit` без развертывания сотен длинных путей в командной строке `CreateProcessW`.

### 2. Синхронизация в clean_accumulator_and_root.ps1 и migrate_to_ddmmyyyyhhmm.ps1
- Во все скрипты очистки интегрировано гарантированное удаление через `\\?\` и `[System.IO.Directory]::Delete`.
- Внедрена полная синхронизация между Накопителем и Запускатором.

### 3. Всеобъемлющее усиление .gitignore
- В `.gitignore` добавлены всеобъемлющие маски:
  * `**/СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/**/УТВЕРЖДЕННЫЕ_ПЛАНЫ_ИЗМЕНЕНИЙ_ПРОЕКТА/**`
  * `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/**/УТВЕРЖДЕННЫЕ_ПЛАНЫ_ИЗМЕНЕНИЙ_ПРОЕКТА/**`
  * `**/_BACKUPS/**/УТВЕРЖДЕННЫЕ_ПЛАНЫ_ИЗМЕНЕНИЙ_ПРОЕКТА/**`
