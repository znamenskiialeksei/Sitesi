## 1. СУТЬ ЗАДАЧИ И ВЫЯВЛЕННЫЕ ПЕРВОПРИЧИНЫ

### 1.1. Сбой фиксации изменений в Git
При попытке пользователя зафиксировать изменения через вкладку Source Control в VS Code возникала критическая системная ошибка:
`Git add failed: fork/exec C:\Program Files\Git\cmd\git.exe: The filename or extension is too long., output: (error ID: 51ff3b4016b54eeba5e480090c65aefb)`

**Корневые первопричины сбоя:**
1. **Сверхдлинные пути [до 343 символов] в сохраненных версиях:**
   В сценарии `create_project_backup.ps1` каталог `УТВЕРЖДЕННЫЕ_ПЛАНЫ_ИЗМЕНЕНИЙ_ПРОЕКТА` ошибочно входил в список копируемых рабочих директорий `$DirectoriesToCopy`. При создании Версии 21 папка планов с длинными именами была скопирована внутрь версии, сформировав путь в 343 символа:
   `c:\...\СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА\villa-turaman-airbnb-platform\142521092026 Версия 21...\УТВЕРЖДЕННЫЕ_ПЛАНЫ_ИЗМЕНЕНИЙ_ПРОЕКТА\003519092026 План Устранения Квадриллионного Бага Валютного Шлюза TCMB и Юр Согласий.md`
   Это превышало лимит Windows `MAX_PATH` [260 символов].
2. **Физическое присутствие поврежденной папки-дубля [293 символа]:**
   Папка `Глольные настройки проекта (запускатор перенос)` с битым символом `\uFFFD` и глубиной путей свыше 290 символов блокировала вызовы Git.
3. **Неотсортированный дубль Версии 21 в корне `СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА`:**
   В корне находилась полная копия Версии 21, дублирующая тысячи файлов.
4. **Лимит командной строки Windows при вызове `git add` из GUI VS Code:**
   При фиксации изменений VS Code передает список файлов аргументами. Переполнение буфера `CreateProcessW` [32 767 символов] вызывало фатальный сбой операционной системы.

### 1.2. Новый глобальный стандарт именования `ДДММГГГГЧЧмм`
По указанию пользователя во всех правилах, регламентах, сценариях и именах версий произведен переход с формата `ЧЧммДДММГГГГ` на канонический формат `ДДММГГГГЧЧмм` [ДеньМесяцГодЧасыМинуты], где время строго следует ПОСЛЕ даты:
- Было: `142521092026 Версия 21...`
- Стало: `210920261425 Версия 21...`

## 2. РЕАЛИЗОВАННЫЕ ИЗМЕНЕНИЯ

1. **Защита Git от длинных путей в `.gitignore`:**
   В корневой `.gitignore` добавлены правила исключения поврежденных папок `*Гло*` и вложенных планов `**/СОХРАНЕННЫЕ_ВЕРСИИ_ПРОЕКТА/**/УТВЕРЖДЕННЫЕ_ПЛАНЫ_ИЗМЕНЕНИЙ_ПРОЕКТА/`.
2. **Исправление сценариев сохранения версий `create_project_backup.ps1`:**
   - Формирование штампа времени переведено на `ddMMyyyyHHmm`.
   - Папка `УТВЕРЖДЕННЫЕ_ПЛАНЫ_ИЗМЕНЕНИЙ_ПРОЕКТА` навсегда исключена из массива копирования `$DirectoriesToCopy`.
   - Внедрена автоматическая очистка вложенных планов и неотсортированных дублей.
3. **Сценарий системной санитаризации `sanitize_git_tree.ps1`:**
   Создан в Накопителе и Запускаторе для оперативного устранения путей длиннее 260 символов, удаления битых папок и переименования версий на новый стандарт `ДДММГГГГЧЧмм`.
4. **Обновление Единого Законодательного Свода `GEMINI.md` и реестра `AGENTS.md`:**
   - Пункт 1.5: канонический формат именования планов зафиксирован как `ДДММГГГГЧЧмм [Имя плана].md`.
   - Пункт 5.2: стандарт именования версий зафиксирован как `ДДММГГГГЧЧмм [Название на русском]`. Введено правило исключения планов из версий для защиты от `MAX_PATH`.
5. **Обновление задач `.vscode/tasks.json`:**
   - Добавлена задача: `🧹 [Глобально] Санитизация дерева файлов и защита от сбоев Git`.
   - Добавлена задача: `💾 [Глобально] Зафиксировать все изменения в Git - Commit All`.
