# Ликвидация localhost и синхронизация Google Sheets с Vercel

## 1. Честный и открытый технический разбор: Почему правки не доходили до сайта

В ходе глубокого сквозного аудита кода и сетевых маршрутов выявлена конкретная первопричина:

### Первопричина №1: Ловушка localhost:3000 в Google Apps Script [Code.js]
1. В процедуре `setupDefaultScriptProperties` по умолчанию прописывался параметр:
   `REVALIDATE_API_URL: http://localhost:3000/api/revalidate`
2. В функции `triggerRevalidateWebhook` [отправка сигнала обновления] стояло выражение:
   `var revalidateUrl = props.getProperty('REVALIDATE_API_URL') || (siteUrl + '/api/revalidate');`
3. Так как свойство `REVALIDATE_API_URL` существовало в памяти Google Таблицы и содержало `http://localhost:3000`, Apps Script пытался отправлять сетевой запрос `UrlFetchApp.fetch` на `http://localhost:3000`.
4. Поскольку скрипт Google Apps Script выполняется на облачных серверах Google Cloud, адрес `localhost:3000` там физически не существует. Сервер Google получал ошибку подключения и прерывал работу функции.
5. Сигнал обновления ни разу не доходил до реального сервера Vercel при ручном нажатии кнопки в меню.

### Первопричина №2: Ограничение простых триггеров Google Sheets при вводе в ячейку
1. В Google Sheets при ручном редактировании ячеек стандартный простой триггер `onEdit` заблокирован политикой безопасности Google: ему запрещено выполнять внешние сетевые запросы `UrlFetchApp`.
2. Для отправки сигнала на Vercel при каждом изменении ячейки требуется Устанавливаемый триггер [Installable Trigger] `onSheetEditTrigger`.
3. Если пользователь не вызвал отдельный пункт меню для создания этого триггера, изменения в ячейках оставались только внутри таблицы и не отправляли вебхук на сайт.

### Первопричина №3: Кэш страниц в браузере и на CDN Vercel
1. На Vercel страницы генерируются статически [Next.js ISR]. Без успешного входящего вебхука ревалидации Vercel продолжал отдавать пользователю старый скомпилированный HTML.
2. В клиентском коде `pages/index.js` запрос свежего контента выполнялся только 1 раз при первой загрузке страницы. При переключении между вкладками браузера сайт не запрашивал повторно данные из таблицы.

## 2. Реализованные системные изменения

1. **Тотальная ликвидация адреса localhost во всех проявлениях:**
   - Во всех функциях `Code.js` (`getEffectiveSiteUrl_`, `triggerRevalidateWebhook`, `setupDefaultScriptProperties`, `setupScriptPropertiesInteractive`, `checkVercelEnvStatusInteractive`) удалены все упоминания `localhost:3000`.
   - Внедрена авто-санация Свойств скрипта: при первом обращении любые остатки `localhost` стираются и перезаписываются боевым URL Vercel.
   - Внедрена функция авто-создания триггера `ensureAutoSyncTriggerInstalled_`: триггер подключается автоматически при первом нажатии кнопки в меню.
   - Во всех API-эндпоинтах (`payment.js`, `payment_success.js`, `system-status.js`, `telegram-webhook.js`) всех трех вариантов платформы `http://localhost:3000` заменен на боевой production домен Vercel.
2. **Мгновенное обновление витрины при возврате на вкладку сайта [pages/index.js]:**
   - Добавлен слушатель события `window.addEventListener('focus', handleWindowFocus)`: при переключении с Google Таблицы на сайт витрина моментально подтягивает свежие данные.
3. **Очистка эндпоинта ревалидации [pages/api/revalidate.js]:**
   - Цель ISR ревалидации сфокусирована на главной странице `/` для исключения предупреждений.
