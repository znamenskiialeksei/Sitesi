## 1. ЦЕЛЬ И ЗАДАЧИ ЭТАПА
1. Утвердить трехуровневый стандарт размещения серверных переменных окружения: 1. Vercel Settings -> Environment Variables ➔ 2. Script Properties в Google Таблице ➔ 3. Локальный `.env.local`.
2. Создать диагностический эндпоинт `/api/system-status` для безопасного аудита ключей без раскрытия их секретных значений.
3. Добавить в меню Google Таблицы интерактивную проверку статуса облачного окружения на Vercel.

---

## 2. АНАЛИЗ ПЕРВОПРИЧИНЫ (ROOT CAUSE)
Ранее регламенты были сфокусированы только на `.env.local` и Script Properties, не формализуя стандарт централизованной настройки переменных на хостинге `https://vercel.com/`. Владелец не имел быстрого способа проверить готовность продакшн-сервера без входа в консоль.

---

## 3. ПОШАГОВЫЙ ПЛАН ИЗМЕНЕНИЙ
1. Создать серверный эндпоинт `pages/api/system-status.js`.
2. В `Code.js` добавить функцию `checkVercelEnvStatusInteractive()` с выводом карточки состояния ключей.
3. Внести каноническое правило 4.4 в `GEMINI.md` и `AGENTS.md`.

---

## 4. РЕЗУЛЬТАТЫ ВЕРИФИКАЦИИ
- Диагностический эндпоинт корректно возвращает маскированный статус ключей.
- Владелец из Google Таблицы в 1 клик проверяет здоровье сервера Vercel.
