# ИНЖЕНЕРНЫЙ ПЛАН: ИСПРАВЛЕНИЕ АВТО-ВОССТАНОВЛЕНИЯ ЛИСТОВ, СОХРАНЕНИЕ ШАПКИ НА СТРОКЕ 1 И ЛИКВИДАЦИЯ СДВИГА 13 КОЛОНОК ACCOUNTS

## 1. Анализ первопричин инцидента

### 1.1. Первопричина 1: Затирание шапки и запись данных в строку 1 в `restoreSheetsFromCloudApiInteractive`
* **Где в коде:** [google-apps-script/Code.js](file:///c:/1%20Вилла%20Сайт%20ГлобПрав%20260920261646/villa-turaman-airbnb-platform/google-apps-script/Code.js#L3245-L3246)
* **Как было:**
  ```javascript
  sheet.clearContents();
  sheet.getRange(1, 1, rectRows.length, maxCols).setValues(rectRows);
  ```
  Функция `sheet.clearContents()` полностью очищала лист, включая заголовок строки 1. Затем `rectRows` (содержащий только строки данных без заголовков) записывался начиная с координаты `(1, 1)` : то есть в первую строку.
* **Следствие:** Заголовок таблицы полностью уничтожался, первая строка данных замещала собой шапку, а формулы автоперевода на строке 2 (`E2`, `F2`) затирали данные второй строки.

### 1.2. Первопричина 2: Сдвиг колонок и отсутствие телефонных номеров в `MASTER_ACCOUNTS_ROWS`
* **Где в коде:** [utils/masterSeedContent.js](file:///c:/1%20Вилла%20Сайт%20ГлобПрав%20260920261646/villa-turaman-airbnb-platform/utils/masterSeedContent.js#L6110-L6141) и заготовки `initSingleSheetByKey_` в [google-apps-script/Code.js](file:///c:/1%20Вилла%20Сайт%20ГлобПрав%20260920261646/villa-turaman-airbnb-platform/google-apps-script/Code.js#L1690-L1692)
* **Как было:**
  ```javascript
  ["2026-01-15", "Алексей Знаменский", "villaturaman@gmail.com", "admin123", "Нет", "Нет", "Нет [Владелец / Главный]", "Верифицирован", "15.01.2026, 12:00:00", "Нет", "Активен", "", "VT-GUEST-1000"]
  ```
* **Следствие:** Колонка 3 [C] листа ACCOUNTS по стандарту предназначена для Телефона (`Номер телефона`), а Email должен находиться в колонке 4 [D]. Из-за выпадения телефонного номера почта `villaturaman@gmail.com` сместилась в колонку C, пароль `admin123` : в колонку D, а статусы сместились вправо. При восстановлении это смещение записывалось прямо в строку 1.

### 1.3. Первопричина 3: Аналогичный дефект записи со строки 1 в `restoreFromDriveSnapshotFileId_`
* **Где в коде:** [google-apps-script/Code.js](file:///c:/1%20Вилла%20Сайт%20ГлобПрав%20260920261646/villa-turaman-airbnb-platform/google-apps-script/Code.js#L3569-L3570)
* **Как было:** `sheet.clearContents(); sheet.getRange(1, 1, rectRows.length, maxCols).setValues(rectRows);` без вызова `styleSheetHeader_`.

## 2. Предлагаемые системные исправления

### 2.1. Исправление `google-apps-script/Code.js` (`restoreSheetsFromCloudApiInteractive`)
1. Выполнять `sheet.clearContents()`;
2. Немедленно восстанавливать темно-синюю шапку: `styleSheetHeader_(sheet, cfg.headers, 1, cfg.minWidths);`;
3. Накладывать Plain Text `@` форматирование:
   * Для `ACCOUNTS`: колонки `C:C`, `E:E`, `M:M`;
   * Для `ACCESS`: колонки `D:D`, `E:E`;
   * Для `BOOKINGS`: колонка `C:C`;
   * Для `GUIDE_ACCESS`: колонка `B:B`;
4. Проверять входящий массив строк: если первая строка содержит дубликат шапки (например, при восстановлении из слепка), отсекать ее через `dataRows = dataRows.slice(1)`;
5. Внедрить авто-санитизацию для `ACCOUNTS`: если колонка 3 содержит знак `@` (почту вместо телефона), автоматически восстанавливать номер телефона и выравнивать 13 колонок;
6. Записывать строки данных СТРОГО со строки 2:
   ```javascript
   sheet.getRange(2, 1, rectRows.length, maxCols).setValues(rectRows);
   ```
7. Устанавливать формулы `MAP/LAMBDA` на строке 2 (`HOME`, `SERVICES`, `GUIDES`, `GALLERY`, `LEGAL`, `TEMPLATES`).

### 2.2. Исправление `google-apps-script/Code.js` (`restoreFromDriveSnapshotFileId_`)
1. Добавить вызов `styleSheetHeader_(sheet, cfg.headers, 1, cfg.minWidths);`;
2. Накладывать текстовые форматы `@`;
3. Отсекать шапку из `item.rows`, если она присутствует в слепке;
4. Записывать данные строго со 2-й строки: `sheet.getRange(2, 1, rectRows.length, maxCols).setValues(rectRows)`.

### 2.3. Исправление `google-apps-script/Code.js` (`initSingleSheetByKey_`)
Зафиксировать эталонные строки `aRows` для `ACCOUNTS` с правильными телефонами и 13 колонками:
* Строка 1: `["2026-01-15", "Алексей Знаменский", "+90 543 335 80 70", "villaturaman@gmail.com", "admin123", "Нет", "Нет", "Нет", "Верифицирован", "15.01.2026, 12:00:00", "Нет", "Активен", "VT-GUEST-1000"]`
* Строка 2: `["2026-05-01", "Служба консьержа", "+90 532 000 00 01", "manager@villaturaman.com", "manager2026", "Нет", "Нет", "Нет", "Верифицирован", "01.05.2026, 10:00:00", "Нет", "Активен", "VT-GUEST-1001"]`

### 2.4. Исправление `utils/masterSeedContent.js`
В массиве `MASTER_ACCOUNTS_ROWS` прописать корректные 13-колоночные строки с телефонами `+90 543 335 80 70` и `+90 532 000 00 01`.

### 2.5. Исправление `scripts/save-master-seed.js`
В блоке выгрузки `ACCOUNTS` добавить защитную нормализацию: если живая таблица временно содержит сдвинутые колонки (вследствие предыдущего теста восстановления), сценарий автоматически выравнивает телефон и email по 13 колонкам, предотвращая порчу эталонного файла при запуске задачи 6.

## 4. Критерии приемки

1. При вызове команды **«🛠️ 1. Авто-восстановление из эталона: Загрузка данных из masterSeedContent.js через Cloud API»** в Google Таблице:
   * Строка 1 каждого листа сохраняет темно-синий заголовок (`styleSheetHeader_`);
   * Строки данных записываются строго начиная со **строки 2**;
   * На листе `ACCOUNTS`: колонка A : дата, колонка B : имя, колонка C : телефон `+90 ...`, колонка D : email `...@...`, колонка E : пароль, колонка M : UID `VT-GUEST-...`;
   * Формулы `MAP/LAMBDA` на строке 2 сохраняются и работают без затирания данных.
2. В файлах `masterSeedContent.js` и `Code.js` заготовки полностью согласованы и не содержат сдвигов колонок.
