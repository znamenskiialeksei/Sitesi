# План: Восстановление видимости заявок и сообщений в кабинете хозяина и смарт-форматирование таблицы чатов

## Описание проблемы и первопричины

1. **Невидимость заявок и сообщений в кабинете хозяина /host:**
   - **Первопричина:** В файле `villa-turaman-airbnb-platform/pages/api/booking.js` в блоке `action === 'master_get_chats'` переменная `allReqs` была объявлена через `const allReqs` **внутри** вложенного блока `try`. В конце метода на строке 1298 происходило обращение к `allReqs` **снаружи** блока `try`. В среде Node.js это вызывало критическую ошибку `ReferenceError: allReqs is not defined`.
   - Внешний блок `catch` перехватывал исключение и возвращал статус `HTTP 500 { success: false, error: 'allReqs is not defined' }`.
   - Из-за этого запрос `fetchMasterChats` в `pages/host/index.js` завершался ошибкой: массивы `chats` и `allRequestsList` оставались пустыми, и хозяин не видел ни одной заявки, ни одного чата.

2. **Отсутствие заголовков и форматирования в таблице чатов:**
   - **Первопричина:** В обработчиках `action === 'request'` и `action === 'booking'` создание новых листов чатов производилось через базовый запрос `addSheet: { properties: { title: chatSheetName } }` без инициализации шапки `GOOGLE_CONFIG.chatHeaders`, без фиксации первой строки и без применения смарт-форматирования. Первое сообщение гостя или системы записывалось прямо в строку 1.
   - Функция `ensureChatSheetExists` была изолирована внутри обработчика `action === 'chat'` и не применялась в смежных точках создания диалогов.

## Предлагаемые изменения

### 1. Серверный API бронирований и чатов

#### [MODIFY] [booking.js](file:///c:/1%20Вилла%20Сайт%20—%20копия%20с%20Глобальными%20правилами%20проекта/villa-turaman-airbnb-platform/pages/api/booking.js)

- **Устранение ReferenceError в `master_get_chats`:**
  - Объявить `let allReqs = [];` и `let allChats = [];` на уровне обработчика действия.
  - Обернуть чтение `bookingDb` в безопасный блок `try/catch` с гарантированным возвратом массива.
  - В цикле чтения сообщений добавить проверку наличия шапки: если в строке 0 находится сообщение, а не `Дата и Время`, считывать строки полностью, не отбрасывая первое сообщение через `slice: 1`.

- **Создание универсального модуля `ensureStyledChatSheet`:**
  - Создание листа с закреплением строки 1: `gridProperties: { frozenRowCount: 1 }`.
  - Запись шапки `GOOGLE_CONFIG.chatHeaders`: `Дата и Время`, `Отправитель`, `Оригинал`, `RU`, `EN`, `TR`, `Ссылка на вложение`.
  - Стилизация шапки: темный премиальный фон `#1e293b`, белый полужирный текст, центрирование по горизонтали и вертикали.
  - Настройка ячеек данных: `wrapStrategy: 'WRAP'`, `verticalAlignment: 'MIDDLE'`.
  - Автоподгонка ширины столбцов под содержимое: `autoResizeDimensions: COLUMNS, 0-7`.
  - **Автоматическое лечение существующих листов:** если лист уже создан без шапки (в ячейке A1 дата, а не `Дата и Время`), вставить строку 0 через `insertDimension`, заморозить строку 1, записать стилизованную шапку и выровнять столбцы без потери данных.

- **Интеграция во все точки создания и обновления чатов:**
  - `action === 'request'`: вызов `ensureStyledChatSheet` перед записью системного сообщения о модерации.
  - `action === 'booking'`: вызов `ensureStyledChatSheet` перед записью сообщения об оплате.
  - `action === 'chat'`: унификация вызова `ensureStyledChatSheet`.
  - `action === 'approve_request'`, `action === 'special_offer'`, `action === 'reject_request'`, `action === 'revoke_request'`: гарантия оформления листа перед отправкой системных уведомлений хозяина.
  - Добавление сервисного действия `action === 'format_chat_sheets'` для единовременного принудительного форматирования всех существующих листов чатов.

## План верификации

### Автоматическая проверка
- Проверка синтаксиса и сборки `npm run build` в `villa-turaman-airbnb-platform`.
- Проверка экспорта и вызовов без `run_command` в соответствии с директивой 1.1 Zero-Terminal Policy.

### Ручная проверка в VS Code
1. Запуск задачи VS Code `🏛️ [Вариант 1 - Airbnb] Инициализация CRM Таблиц - Google Sheets` для мгновенного форматирования всех листов чатов.
2. Проверка Google Таблицы чатов: наличие темной шапки, закрепленной строки 1, красивых столбцов с автошириной.
3. Открытие кабинета хозяина `/host`: проверка появления всех заявок во вкладке «Заявки и брони» и всех диалогов во вкладке «Сообщения CRM».
4. Отправка тестового сообщения или создание заявки: проверка автоматического сохранения идеального форматирования.
