## 1. ЦЕЛЬ И ЗАДАЧИ ЭТАПА
1. Устранить ошибку Source Control в VS Code: `Git add failed: The filename or extension is too long`.
2. Реализовать принудительное удаление путей свыше 260 символов через расширенный системный Win32 API префикс `\\?\`.
3. Очистить индекс Git от старых отслеживаемых сверхдлинных путей и перевести все изменения в Staged Changes.

---

## 2. АНАЛИЗ ПЕРВОПРИЧИНЫ (ROOT CAUSE)
Вложенные папки планов внутри версий создавали пути длиной до 373 символов, превышавшие предел Windows MAX_PATH (260). Стандартный `Remove-Item` в PowerShell завершался ошибкой, а кнопка Commit в VS Code передавала длинные аргументы в `CreateProcessW`.

---

## 3. ПОШАГОВЫЙ ПЛАН ИЗМЕНЕНИЙ
1. В `sanitize_git_tree.ps1` реализовать функцию `Remove-LongPathItem` через `[System.IO.Directory]::Delete`.
2. Внедрить команду `git rm -r --cached` для исключения старых длинных путей.
3. Добавить автоматический вызов `git add -A` в сценарии санитизации.
4. В корневой `.gitignore` добавить исключения для вложенных планов.

---

## 4. РЕЗУЛЬТАТЫ ВЕРИФИКАЦИИ
- Сверхдлинные пути физически уничтожены через системный API Windows.
- Кнопка Commit в интерфейсе VS Code работает мгновенно и безошибочно.
