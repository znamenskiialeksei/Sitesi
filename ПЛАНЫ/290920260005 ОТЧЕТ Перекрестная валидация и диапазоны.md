## 1. СИСТЕМНЫЙ РАЗБОР ПЕРВОПРИЧИН И ОТВЕТЫ НА ВОПРОСЫ ПОЛЬЗОВАТЕЛЯ

### 1.1. Вопрос: «Почему это стало происходить, если до этого все работало исправно?»
1. **Сбой в Google Apps Script (`Code.js`):**
   - **Симптом:** `TypeError: Cannot read properties of undefined (reading 'length')` при вызове Меню 5.1 («🛠️ 1. Авто-восстановление из эталона»).
   - **Первопричина:** На предыдущем шаге в `Code.js` была внедрена темно-синяя шапка через вызов `styleSheetHeader_(sheet, cfg.headers, 1, cfg.minWidths)`. Однако в объекте `VILLA_SHEETS_CONFIG` свойство `headers` исторически **никогда не существовало** (там были только `sheetId`, `name`, `minWidths`, `icon`). До этого шага шапка вообще не генерировалась из `VILLA_SHEETS_CONFIG`, поэтому `cfg.headers` никто не запрашивал. При первом же реальном вызове код упал на обращении к `headers.length`.
2. **Сбой в Node.js CLI (`scripts/restore-sheets.js`):**
   - **Симптом:** `Invalid data[6]: Requested writing within range ['🔑 Управление доступом'!A2:G6], but tried writing to column [H]`.
   - **Первопричина:** В коде `restore-sheets.js` блоки заполнения данными были обернуты условием холодного старта: `if (rowCount <= 1)`. Пока в таблице существовали листы со строками данных, это условие **никогда не выполнялось** (ветка `rowCount > 1` просто пропускалась). Когда пользователь удалил листы в таблице для проверки чистого восстановления, условие `rowCount <= 1` впервые активировалось. Скрипт попытался записать эталонную матрицу `MASTER_ACCESS_ROWS`, которая содержала 8 колонок (A..H), в жестко захардкоженный диапазон `A2:G6` (7 колонок: A..G). Google Sheets API вернул ошибку размерности HTTP 400.

### 1.2. Вопрос: «Почему это не исправляется попутно при решении других задач?»
- **Эффект локальной изоляции правок:** Предыдущие задачи были сфокусированы на синхронизации 13 колонок листа `ACCOUNTS` и полях витрины. Проверка работоспособности холодного старта других листов (например, листа `ACCESS`) не проводилась, так как проверялись только измененные ветки.
- **Отсутствие сквозного мандата перекрестной валидации:** Не было нормативно закрепленного глобального правила, предписывающего проверять сигнатуры конфигураций (`VILLA_SHEETS_CONFIG`) и симметрию размерностей массивов данных во всех смежных сценариях восстановления перед сдачей работ.

## 2. НОВЫЕ ГЛОБАЛЬНЫЕ ПРАВИЛА В ЕДИНОМ СВОДЕ (ПРАВИЛА 1.10 - 1.14)

В Единственный Законодательный Свод [GEMINI.md](file:///c:/1%20Вилла%20Сайт%20ГлобПрав%20260920261646/GEMINI.md), [AGENTS.md](file:///c:/1%20Вилла%20Сайт%20ГлобПрав%20260920261646/AGENTS.md) и [Накопитель GEMINI.md](file:///c:/1%20Вилла%20Сайт%20ГлобПрав%20260920261646/Глобальные%20настройки%20проекта%20(накопитель)/GEMINI.md) включены и закреплены следующие обязательные правила:

1. **Правило 1.10: Принцип глобальной перекрестной проверки взаимосвязей и зависимостей [Cross-System Dependency & Ripple-Effect Validation Mandate]:**  
   Любое изменение сущности, структуры листа, набора колонок или параметров вызова функций обязано сопровождаться сквозной перекрестной проверкой ВСЕХ зависимых файлов репозитория: `Code.js`, `masterSeedContent.js`, `content.json`, `restore-sheets.js`, `save-master-seed.js`, API-роутов и компонентов витрины. Запрещено завершать задачу без полной верификации всей цепочки.
2. **Правило 1.11: Запрет скрытых и невалидированных обращений к свойствам конфигураций [Defensive Configuration & Schema Parity Policy]:**  
   Категорический запрет на обращение к полям конфигурационных объектов без гарантии их фактического присутствия в схеме (`cfg.headers.length` без объявления `headers` в `cfg`). Все конфигурационные объекты обязаны содержать полный набор деклараций, а код - защитные проверки fallback.
3. **Правило 1.12: Принцип динамических диапазонов Google Sheets API [Dynamic Bounding Range Mandate]:**  
   Тотальный запрет на хардкод строковых диапазонов с фиксированными колонками (`A2:G6`) для записи динамических матриц данных. Диапазон обязан вычисляться динамически по фактической размерности массива данных: `getBoundingRange(sheetName, startCol, startRow, matrix)`.
4. **Правило 1.13: Мандат зеркальной синхронизации скриптов самоисцеления и восстановления листов [Restore Scripts Synchronicity Mandate]:**  
   Любые доработки процедур восстановления листов в `Code.js` (Google Apps Script) обязаны зеркально воспроизводиться в локальном сценарии `scripts/restore-sheets.js` (Node.js) и наоборот. Оба инструмента должны поддерживать идентичный набор из 15 листов, одинаковые колонки, единые правила форматирования и структуры.
5. **Правило 1.14: Принцип сквозного тестирования ветвей холодного старта и пустых данных [Cold-Start & Zero-Data Boundary Testing]:**  
   При любых правках механизмов восстановления и инициализации данных агент обязан моделировать сценарии холодного старта: полная очистка листа, отсутствие строк, развертывание с нуля.
